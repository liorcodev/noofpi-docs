# Internationalization

noofpi ships typed i18n. Enable it in the config and add one file per locale in `app/locales/`.

## Configuration

```ts [noofpi.config.ts]
import { defineNoofpiConfig } from "noofpi";

export default defineNoofpiConfig({
  i18n: { locales: ["en", "he"], defaultLocale: "en" }, // defaultLocale falls back to the first locale
});
```

See [Configuration](/docs/core-concepts/configuration) for all options.

## Messages

`defineMessages` and `useI18n` are auto-imported. The default locale defines the keys:

```ts [app/locales/en.ts]
export default defineMessages({
  home: { title: "Home" },
  greeting: "Hello, {name}!",
  inbox: "no messages | one message | {count} messages",
});
```

Other locales provide the same keys. Add `satisfies LocaleMessages<typeof en>` so the compiler checks them:

```ts [app/locales/he.ts]
import type { LocaleMessages } from "noofpi/runtime";
import type en from "./en";

export default defineMessages({
  home: { title: "בית" },
  greeting: "שלום, {name}!",
  inbox: "אין הודעות | הודעה אחת | {count} הודעות",
}) satisfies LocaleMessages<typeof en>;
```

## Using messages

```vue [app/pages/index.vue]
<script setup lang="ts">
const { t, locale, setLocale } = useI18n();
</script>

<template>
  <h1>{{ t("home.title") }}</h1>
  <p>{{ $t("greeting", { name: "Ada" }) }} {{ t("inbox", { count: 3 }) }}</p>
  <button @click="setLocale(locale === 'en' ? 'he' : 'en')">
    {{ locale }}
  </button>
</template>
```

| API                  | Description                                                                  |
| -------------------- | ---------------------------------------------------------------------------- |
| `t(key, params)`     | Translate a key, available from `useI18n()`                                  |
| `$t(key, params)`    | The same function, available in templates                                    |
| `locale`             | The active locale                                                            |
| `setLocale(locale)`  | Switch locale and store it in the `noofpi-locale` cookie. Returns a promise  |
| `ready`              | A promise that settles when the initial and default locales are loaded       |

## Typing

noofpi generates `.noofpi/i18n.d.ts` from the default locale's file on `dev` and `build`. With it:

- `t()` only accepts keys that exist, such as `"home.title"`.
- `{name}` placeholders are required as typed params.
- `setLocale()` is typed with the locales from the config.

Typed params need `defineMessages`, which keeps the texts literal. JSON files give `string` keys with loose params.

Include the generated declarations in your `tsconfig.json`:

```json [tsconfig.json]
{
  "compilerOptions": { "types": ["vite/client", "noofpi/client"] },
  "include": ["app", "server", ".noofpi/*.d.ts"]
}
```

## Locale detection

The locale is resolved in this order:

1. The `noofpi-locale` cookie, set by `setLocale()`.
2. The browser's `Accept-Language` header.
3. `defaultLocale`.

The server hands the locale it rendered in to the browser, so hydration always matches.

## HTML lang and dir

`<html lang dir>` follow the locale, with `dir="rtl"` for Hebrew, Arabic and other right-to-left languages. A page's `useHead({ htmlAttrs })` can override them. See [Head](/docs/core-concepts/head).

## Plurals

Write plural forms as `one | many` or `none | one | many`. The form is picked by `params.count`.

```ts
inbox: "no messages | one message | {count} messages";
```

## Fallback

A message a locale lacks comes from the default locale. If that is missing too, `t()` returns the key.

## Lazy loading

In the browser, locales load on demand, so a visitor only downloads the languages they use.

- Before the first render, the browser loads the messages of the active locale and of the default
  locale, which is the fallback.
- Other locales load when `setLocale()` switches to them.
- The server bundles every locale, so server-rendered pages never wait for a file.

`setLocale()` returns a promise that resolves once the new locale is active. If loading fails, the
promise rejects and the current locale stays. If the user switches again while a locale is still
loading, the newest call wins.

```vue
<script setup lang="ts">
const { locale, setLocale } = useI18n();

async function switchTo(next: "en" | "he") {
  try {
    await setLocale(next);
  } catch {
    // the previous locale is still active
  }
}
</script>
```

`ready` is a promise that settles when the initial and default locales are loaded. Use it if you
need the messages before running code outside a component render.

## Limitations

::Callout{type="note" title="Dotted paths"}
Messages are addressed by dotted paths, so message keys cannot contain `.`.
::
